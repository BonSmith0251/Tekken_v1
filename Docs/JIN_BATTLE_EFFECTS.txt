JIN BATTLE EFFECTS (LocalVersus / LocalVersus2 / CharacterEffectsShowcase)

Jin now dispatches his original timed character effect from move property 0x802E:
143 events across 51 moves, verified against the original jinmot.bin. The native
code selects character effect ID 0, which BP_jinEffectManager binds to
PS_EF_CHR_JIN_NOMAL. The property value supplies the bone ID; both the effect owner
and bone owner are Jin. This is a move-frame effect, including on a whiff.

BattleModel publishes the acted move and source frame, including the outgoing
frame of a transition. VersusGame queues the events until the actors are posed;
CharacterBattleEffects resolves Jin's own registry and native bone map. Round
reset clears the effect instances. The same dispatcher serves the action preview.

The original Jin VBN table has 177 entries: ID 7 is R_Arm, not R_Hand (ID 9).
Native PM_CharacterBone reads BonePlayerNumber and BoneIndex, then replaces its
stored SourceLocations[0]. Thus NOMAL's packaged Neck entry is overridden for
these timed events. The native constructor and update gate show that new particles
use the current bone, while existing particles do not follow it. Unity supplies
the resolved source-bone override and world-space simulation accordingly.

Source-backed data and Unity adaptations:
  Original packages, native code and moveset records establish the binding,
  event frames, owner, bone IDs and dynamic bone selection. Source atlas grids,
  frame-index curves and linear/linear-blend interpolation are retained and used
  by the renderer; NOMAL's atlas is no longer displayed as an entire texture sheet.
  Raw properties, module/LOD records and hashes remain in the conversion report.

  Rendering still uses the shared Cascade-to-Unity adaptation: first stored LOD,
  sampled distributions, particle caps, shader/material selection, brightness
  and alpha handling. Native spawn rotation derives from actor facing; Unity uses
  the displayed actor rotation. The native point conversion includes +10 Unreal
  units vertically; the installed manifest uses +0.1 m for the instance origin.
  Its equivalence to the retargeted rig's origin still needs an original capture
  comparison. The PM_CharacterBone sprite uses its resolved rig bone directly,
  with zero offset. Multiple simulation ticks retain their events but use the
  next displayed pose. These choices do not establish visual parity.

Still unresolved:
  Collision-driven character effects and their native conditions are not wired
  by this work. Inherited Blueprint OnHit is empty; that does not mean the native
  game has no collision effects. Existing common impact effects are a separate
  system (see BATTLE_EFFECTS.txt), not evidence for Jin-specific hit dispatch.
  The other 17 catalog systems have no verified move bindings here, including
  unique1..4 and item variants. Random atlas modes, custom socket cases such as
  PatoLight's Head_Socket, update-each-frame variants, nonzero bone-local offsets,
  native mesh rotation details, refraction and omitted shader operations remain
  limited or unsupported. Missing sockets are not replaced with guessed bones.
